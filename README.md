# kohaku-roleplay

面向 KohakuTerrarium 桌面单用户的酒馆角色卡扩展，目标兼容 KT v2.2.2。已有 creature 的形象挂载、单 agent 酒馆和逐角色 agent 小说使用同一素材库；剧情与人物经历只属于当前会话。

## 使用

在插件仓库执行 `kt install . -e --no-deps` 安装到目标 KT 主机，再重载桌面。只在工作区做开发验证时使用工作区专属虚拟环境及 `KT_CONFIG_DIR`，不要将测试卡装入日用 KT。

- 人物形象：在已发现本包的 creature 的插件列表启用 `roleplay`，在会话侧栏确认形象后应用；移除仅影响之后的模型请求。
- 酒馆：使用角色库的开局入口，或启动 `@kohaku-roleplay/creatures/rp_agent` 后在侧栏选卡、玩家身份和开场。
- 小说（实验性）：从角色库选择演员卡开局，在 root 聊天中输入行动。root 分配角色视角，收到所有必要回报后才裁定；打开侧栏查看状态不会推进剧情。若缺少回报，本幕不会自动替该角色作决定。新局不读取旧局。

## 小说幕的恢复

裁定同时写入 root 的本局事实和每名收件 NPC 自己的私有记录，不用再唤醒 NPC。若中断在裁定前，恢复原会话后可以在小说侧栏重试当前幕：已有回报不重演，只给缺报且空闲的角色重发原视角；若回报已齐，只请 root 完成本幕。重试不是新的玩家输入，也不会补造缺失的回报。

## 卡作者：声明本局状态

在酒馆卡 `data.extensions["kohaku-roleplay"].state` 放字段数组；没有此扩展的卡无需改动。每个字段需要 `key`、`label`（显示名）、`type`、`initial`（初值）和 `visibility`（`public` 或 `private`）。`key` 在同一张卡中唯一，以 ASCII 字母开头，之后可用字母、数字、`_`、`-`，总长不超过 64 个字符。

| `type` | 值及约束 |
| --- | --- |
| `text` | 字符串 |
| `number` | 有限数值；可选 `min`、`max`，初值与更新均须在范围内 |
| `enum` | 字符串；`options` 是非空、不重复的候选列表，值须在列表内 |
| `list` | 字符串数组，可为空 |

酒馆由 `rp_agent` 在需要时更新本局字段值；小说由 root 在幕裁定时写入受影响角色的字段。错误或未声明的更新整批拒绝。侧栏只投影 `public` 字段，普通 creature 的形象挂载不加载这些定义。`private` 不意味着对宿主操作者加密，单用户仍可以检查原卡、工具调用和调试记录。开局后的变化不会改写卡库或串入新会话。

## 项目文件地图

- `kohaku.yaml`：KT 包清单；`creatures/rp_agent/`：单 agent 酒馆配置与角色行为。
- `kt_roleplay/`：后端，含卡片解析、素材库、人物形象/游玩投影和世界书筛选；`card_state.py` 定义卡片状态协议，`state_tool.py` 提供酒馆更新工具，`novel.py` / `scene_tools.py` / `recovery.py` 处理小说裁定、分发回报与中断恢复。
- `ui/`：KT UI SDK 扩展，包含角色库、会话侧栏、行动选项与语言资源。

## 兼容范围

角色卡优先使用 PNG / JSON V2；支持 V1 基础字段及 V3 的兼容子集。未知扩展保存在导入的原件中，不执行第三方脚本或自动下载外部资源。已有会话保留开局时的角色文字设定；删除库中卡片不会删除已发生的对话，但之后不能再从素材库读取该卡头像。

酒馆会话可单独绑定或解除 JSON 世界书，不影响卡内世界书或其他会话。小说模式允许玩家直接输入行动，由 root 判断哪些角色应当察觉，不必手动点名。多人一幕需要多次模型请求；参数重试以及 KT Studio 自动生成的会话摘要也可能产生调用。侧栏只展示公开状态，不保证模型生成的自由正文永不串视角。耗时、角色选择和长局一致性取决于所选模型与卡片，小说模式仍为实验性。
